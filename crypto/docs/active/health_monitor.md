**2026-10-21修订：盈亏比/Sharpe触发审查不再默认导向暂停。** 原规则隐含"审查后可能暂停"，经事后回算验证（17次历史触发事件扩展样本，见`strategy_research_log.md`对应条目）证伪：暂停30天档8好8差1平，暂停50天档6好11差，没有证据支持暂停能带来正收益，50天档反而明显偏差（暂停越久越容易错过随后的修复/反弹）。根因是这类指标是结果性/滞后触发，不同于`pause_mechanism.md`价格+波动率+动量的前瞻性触发，两者不能类比。因此触发审查后的动作改为归因记录（用`attribution_check.py`跑客观化检查），不再将"是否暂停"作为选项——2026-10-21第二轮调研进一步验证了胜率/Sharpe/MFE比值/CUSUM变点检测四个候选指标单独使用及两两、三组合联合使用，没有一个组合支持"触发后暂停"，说明问题不是"原指标不够好、换个指标或组合就行"，而是这类事后性能指标本身（无论单独还是组合）都是结果性/滞后触发，不具备判断是否暂停的能力。归因记录的作用仅限于帮助理解"为什么变差"，不构成暂停的依据——即使归因指向消息面冲击等系统性因子，也不能从这套回顾性指标框架里推导出"应该暂停"的结论；如果确实需要应对系统性因子，那是独立于本框架的人工判断，不是本框架能支持的例外。

## 设计说明（稳定不变，非当前状态）

**为什么胜率阈值按策略类型拆分：** 原为全策略统一37.5%/30%，用实盘部署8个策略全历史数据核实后发现v3_205m（长周期版本）历史均值胜率仅27.9%，中位数27.0%，用30%这条统一线会让v3_205m系列几乎永远处于"破线"状态（74%的历史窗口都低于30%），阈值形同虚设。改为按策略类型分别设定，方法与盈亏比阈值一致（历史基准-20%相对预警）：v2类历史均值33.8%，阈值27%；v3_205m类历史均值27.9%，阈值22%（2026-08-14）。

**为什么只用盈亏比作为触发条件，胜率不单独触发：** 本策略是低胜率（31-37%）+高盈亏比的双向趋势跟踪结构，盈利来源是少数大赢的趋势单覆盖多数小额止损，不是靠胜率取胜（详见 `docs/background/trend_following_research.md`）。胜率在小样本滚动窗口下天然噪声极大（v3_205m类历史上52%-74%的窗口都低于统一30%线，属于正常特征而非异常），单独用胜率触发会产生大量假阳性。`trend_following_research.md` 定义的胜率触发条件是"持续低于30%**且盈亏比同时下降**"——即胜率是联合判据，不是独立判据。实践中两个真正触发审查的案例（BTC_v2、SOL_v2）盈亏比连续破线时胜率也同步走低，联合关系是成立的，因此只用盈亏比作触发条件不会漏判，胜率仅作为归因阶段的参考信号。

**胜率观察名单机制：** 胜率不单独触发审查，但也不应完全被忽略——单独触发会产生大量假阳性（历史上部分策略连续2月破线高达21次/70窗口），但完全不追踪会让"胜率是联合判据"变成"胜率被无视"。做法：每月监控时，把当月胜率破线的策略记入观察名单；下月审查时重点检查这些策略的盈亏比是否同步走弱。如果同步走弱，联合判据条件满足，即使盈亏比尚未连续2个月破线也应提前介入归因；如果盈亏比保持健康，说明是胜率的正常噪声，从观察名单移除（2026-08-14新增）。

**"回撤/历史最大回撤1.5倍"规则的盲点（2026-10-21发现）：** 该规则假设"创新高后不退、后续又来一波更深"才会触发，但当前回撤正处于创历史新高的过程中时，分子（当前回撤）和分母（历史最大回撤）是同一个数，比值恒为1.0x，永远不可能达到1.5x——除非先阶段性恢复、再二次探底更深。BTC_ema/BTC_v2 2026年10月的案例：当前回撤（32.1%/30.3%）本身就是历史新高，是历史第二深回撤（17.0%/14.5%）的1.9-2.1倍，深度已严重异常，但"倍数"规则读数仍是1.00x，无法反映这一点。处理方式：触发审查后，归因阶段额外对比"当前回撤深度 vs 历史第二深回撤"，不能只看"当前/历史最大"这一个比值。

**为什么补入滚动Sharpe但不补入连续亏损次数/回撤持续时间：** `trend_following_research.md` 定义了三个未被本表采纳的候选指标——连续亏损次数（>10次触发）、滚动12月Sharpe（连续2-3个月<0触发）、回撤持续时间。用实盘部署8个策略全历史核实：连续亏损次数历史最长普遍13-23笔，"10次"这条线早被反复突破，与胜率统一30%线同样的问题（阈值未按策略校准，形同虚设），不予采纳。滚动Sharpe历史触发频率与盈亏比规则量级接近（多数策略0次，个别策略连续2月<0约13-14%窗口），且实测抓到DOGE_v2一个盈亏比规则漏判的案例，故补入触发表。回撤持续时间未采纳为通用规则：8个标的高度相关（同属市场级横盘磨损），"90分位"对高度相关样本没有独立验证意义，不适合做成阈值规则，但作为归因阶段的参考信号有效（2026-08-14）。

## 审查流程

触发审查后**默认不暂停**（2026-10-21修订，理由见触发规则表下方说明），先做归因记录，供后续月份参考。**用 `analysis/attribution_check.py --key {策略key} --recent 30` 跑一遍客观化检查**（2026-10-21新增，替代纯人工读图判断）：

1. **消息面冲击？** 脚本维度1：近N笔内是否存在超过全历史均值亏损1.5倍的异常大亏损，剔除后盈亏比是否显著回升。
2. **横盘磨损？** 脚本维度2：近N笔平均持仓K线数 vs 全历史均值的比值，<0.7视为显著偏离。
3. **趋势耗尽/假突破增多？** 脚本维度3：近N笔MFE（有利波动%）中位数 vs 全历史中位数的比值，<0.7视为显著收窄（比维度2更精细，能区分"趋势变短但方向仍对"和"入场质量下降"）。
4. **系统性环境 vs 个体退化？** 脚本维度4：同期是否有其他策略也触发审查（同一批触发事件里≥2个独立策略同期破线，倾向系统性市场环境问题，不宜只对单一策略做参数调整）。

四项输出仅供归因记录参考，**不作为暂停决策的依据**——脚本不自动下暂停/继续的结论，归因本身也不能推导出"应该暂停"。设计背景：2026-10-21第一轮调研曾认为"审查后是否暂停"样本量太小（仅6次独立触发事件）无法验证，第二轮调研放宽阈值将样本扩大到17次后重新回算，结果证伪了暂停的正向效果（暂停30天档8好8差1平，50天档6好11差）；第三轮系统验证胜率/Sharpe/MFE比值/CUSUM四个候选指标单独及两两、三组合联合使用，三层回算全部证伪，确认根因不是指标选得不好，而是这类事后性能指标结构上就不具备判断暂停的能力，不存在"归因指向系统性因子就可以例外暂停"这条路（详见 `strategy_research_log.md` 对应条目）。

- 焦虑时对照这张表，指标没触发就是噪声
- 单次不符合预期不触发调整，需要连续2次
- 胜率37%的策略，连续8次亏损概率2.5%，属于正常范围
- 要判断策略真正失效，需要至少50-100笔交易的滚动样本

滚动盈亏比也可以在 TradingView 策略里直接画，参考 Pine Script v6 实现：

```pine
N = input.int(30, "滚动窗口（笔数）")
total_trades = strategy.closedtrades
start_idx = math.max(0, total_trades - N)
float sum_profit = 0.0
float sum_loss = 0.0
int count_profit = 0
int count_loss = 0
for i = start_idx to total_trades - 1
    pnl = strategy.closedtrades.profit(i)
    if pnl > 0
        sum_profit += pnl
        count_profit += 1
    else if pnl < 0
        sum_loss += math.abs(pnl)
        count_loss += 1
avg_profit = count_profit > 0 ? sum_profit / count_profit : 0.0
avg_loss   = count_loss  > 0 ? sum_loss  / count_loss  : 0.0
rolling_rr = avg_loss > 0 ? avg_profit / avg_loss : 0.0
plot(rolling_rr, "滚动盈亏比", color=color.blue, linewidth=2)
hline(2.26, "历史均值", color=color.green)
hline(1.58, "预警线", color=color.red, linestyle=hline.style_dashed)
```
