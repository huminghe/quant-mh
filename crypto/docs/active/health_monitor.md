## 设计说明（稳定不变，非当前状态）

**为什么胜率阈值按策略类型拆分：** 原为全策略统一37.5%/30%，用实盘部署8个策略全历史数据核实后发现v3_205m（长周期版本）历史均值胜率仅27.9%，中位数27.0%，用30%这条统一线会让v3_205m系列几乎永远处于"破线"状态（74%的历史窗口都低于30%），阈值形同虚设。改为按策略类型分别设定，方法与盈亏比阈值一致（历史基准-20%相对预警）：v2类历史均值33.8%，阈值27%；v3_205m类历史均值27.9%，阈值22%（2026-08-14）。

**为什么只用盈亏比作为触发条件，胜率不单独触发：** 本策略是低胜率（31-37%）+高盈亏比的双向趋势跟踪结构，盈利来源是少数大赢的趋势单覆盖多数小额止损，不是靠胜率取胜（详见 `docs/background/trend_following_research.md`）。胜率在小样本滚动窗口下天然噪声极大（v3_205m类历史上52%-74%的窗口都低于统一30%线，属于正常特征而非异常），单独用胜率触发会产生大量假阳性。`trend_following_research.md` 定义的胜率触发条件是"持续低于30%**且盈亏比同时下降**"——即胜率是联合判据，不是独立判据。实践中两个真正触发审查的案例（BTC_v2、SOL_v2）盈亏比连续破线时胜率也同步走低，联合关系是成立的，因此只用盈亏比作触发条件不会漏判，胜率仅作为归因阶段的参考信号。

**胜率观察名单机制：** 胜率不单独触发审查，但也不应完全被忽略——单独触发会产生大量假阳性（历史上部分策略连续2月破线高达21次/70窗口），但完全不追踪会让"胜率是联合判据"变成"胜率被无视"。做法：每月监控时，把当月胜率破线的策略记入观察名单；下月审查时重点检查这些策略的盈亏比是否同步走弱。如果同步走弱，联合判据条件满足，即使盈亏比尚未连续2个月破线也应提前介入归因；如果盈亏比保持健康，说明是胜率的正常噪声，从观察名单移除（2026-08-14新增）。

**为什么补入滚动Sharpe但不补入连续亏损次数/回撤持续时间：** `trend_following_research.md` 定义了三个未被本表采纳的候选指标——连续亏损次数（>10次触发）、滚动12月Sharpe（连续2-3个月<0触发）、回撤持续时间。用实盘部署8个策略全历史核实：连续亏损次数历史最长普遍13-23笔，"10次"这条线早被反复突破，与胜率统一30%线同样的问题（阈值未按策略校准，形同虚设），不予采纳。滚动Sharpe历史触发频率与盈亏比规则量级接近（多数策略0次，个别策略连续2月<0约13-14%窗口），且实测抓到DOGE_v2一个盈亏比规则漏判的案例，故补入触发表。回撤持续时间未采纳为通用规则：8个标的高度相关（同属市场级横盘磨损），"90分位"对高度相关样本没有独立验证意义，不适合做成阈值规则，但作为归因阶段的参考信号有效（2026-08-14）。

## 审查流程

触发审查时，先做归因再决定是否调整：

1. **消息面冲击？** 把异常大亏损（超过正常止损1.5倍）剔除，重新计算盈亏比。如果剔除后回到正常范围，是外部冲击，不是策略问题。

2. **横盘磨损？** 看当前市场是否处于低波动横盘状态（ADX < 20，布林带收窄）。如果是，等待市场方向确立，暂停机制是主要应对手段。

3. **策略本身失效？** 排除以上两种情况后，盈亏比仍然持续低位，才考虑策略参数审查。

## 心态管理原则

- 焦虑时对照这张表，指标没触发就是噪声
- 单次不符合预期不触发调整，需要连续2次
- 胜率37%的策略，连续8次亏损概率2.5%，属于正常范围
- 要判断策略真正失效，需要至少50-100笔交易的滚动样本

滚动盈亏比也可以在 TradingView 策略里直接画，参考 Pine Script v6 实现：

```pine
N = input.int(30, "滚动窗口（笔数）")
total_trades = strategy.closedtrades
start_idx = math.max(0, total_trades - N)
float sum_profit = 0.0
float sum_loss = 0.0
int count_profit = 0
int count_loss = 0
for i = start_idx to total_trades - 1
    pnl = strategy.closedtrades.profit(i)
    if pnl > 0
        sum_profit += pnl
        count_profit += 1
    else if pnl < 0
        sum_loss += math.abs(pnl)
        count_loss += 1
avg_profit = count_profit > 0 ? sum_profit / count_profit : 0.0
avg_loss   = count_loss  > 0 ? sum_loss  / count_loss  : 0.0
rolling_rr = avg_loss > 0 ? avg_profit / avg_loss : 0.0
plot(rolling_rr, "滚动盈亏比", color=color.blue, linewidth=2)
hline(2.26, "历史均值", color=color.green)
hline(1.58, "预警线", color=color.red, linestyle=hline.style_dashed)
```
