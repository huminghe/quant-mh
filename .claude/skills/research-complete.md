# research-complete

研究完成后，按以下步骤逐一检查，每步完成后打勾确认。

## 步骤 1：验证研究日志格式

读取最近更新的研究日志（`crypto/docs/active/strategy_research_log.md` 或 `a_stock/docs/factor_research_log.md`），检查最新条目是否包含以下所有字段：

- [ ] `**结论：**`
- [ ] `**数据：**`（时间范围、标的数量）
- [ ] `**测试规模：**`（n_trials=N）
- [ ] `**参数选择理由：**`
- [ ] `**过拟合风险：**`（低/中/高）
- [ ] `**样本外验证：**`（有/无）
- [ ] `**排除的方向：**`
- [ ] `**细节：**`
- [ ] `**下一步：**`

缺少任何字段时，提示用户补充，不要跳过。

## 步骤 2：检查分析脚本

检查本次研究产生的脚本是否已保存到项目目录：

```bash
# 检查 /tmp 中是否有最近修改的 .py 文件
find /tmp -name "*.py" -mtime -1 2>/dev/null
```

如果有未保存的脚本，提示用户将其移动到 `crypto/analysis/` 或 `a_stock/` 对应目录，并按命名规范重命名（`{主题}_{功能}.py`）。

## 步骤 3：提示更新 memory

根据本次研究结论，判断以下哪些 memory 文件需要更新：

- 如果结论涉及策略优化方向 → 检查 `project_crypto_optimization_roadmap.md` 是否需要更新
- 如果结论涉及标的筛选 → 检查 `project_token_selection.md` 是否需要更新
- 如果结论推翻了之前的认知 → 找到对应 memory 文件，更新或删除过时内容
- 如果是全新的重要结论 → 建议创建新的 memory 条目

列出需要更新的文件，等用户确认后再修改。

## 步骤 4：检查 CLAUDE.md 是否需要更新

判断本次研究是否产生了新的规范或约束：

- 如果发现了新的数据处理规范 → 更新 `.claude/rules/trading-standards.md`
- 如果发现了新的研究方法规范 → 更新 `crypto/docs/background/research_workflow.md`
- 如果 Claude 在本次研究中犯了错误 → 更新 `.claude/lessons.md`

## 步骤 5：生成收尾摘要

输出一段简短的收尾摘要，格式：

```
## 研究收尾摘要 YYYY-MM-DD

**核心结论：** [一句话]
**日志：** [已更新 / 待补充字段：XXX]
**脚本：** [已保存 N 个 / 待保存：XXX]
**Memory：** [已更新 / 无需更新]
**下次继续：** [下一步行动]
```
