# Lessons Learned

Claude 在此项目中被纠正的错误和对应规则。每次被纠正时自动追加，不需要用户提醒。

交易规范（复权方式、T+1、回测验收标准等）在 `.claude/rules/trading-standards.md`，不在此文件重复。

---

- [archive 归档标准]："决策已执行"不能作为归档理由。执行了的决策文档记录的是"为什么这样做"，是当前配置的依据，恰恰需要保留在主路径。归档条件是：内容已被其他文档完全吸收 AND 原文档不再有独立参考价值。用户说"可以先做 X 再做 Y"，不代表"允许跳过 X"，而是"先做 X，再做 Y"的顺序指令。有歧义时先确认，不要默认跳过。
- [规则提炼]：完成非 trivial 任务（文件整理、架构决策、调研结论）后，不能只做事不总结。做完后要主动把确定的规则写进 CLAUDE.md 或 memory，并询问用户是否需要固化。否则下次遇到同类情况还是会走老路。
- [数据合并时区]：TV 导出交易记录是 UTC+8 naive datetime，Binance API 是 UTC。合并前必须先将 TV 时间 -8h 转 UTC，否则等效于用了未来 8 小时数据。这是系统性错误，会导致所有正向结论都是假的。
- [正向结论要更怀疑]：在量化验证中，某个过滤器突然出现正向结论时，应先检查数据管道（时区、lookahead、数据对齐），而不是直接相信结论。负向结论通常更可信，正向结论更可能是数据泄漏。
- [总结检查清单要在 compact 前完成]：CLAUDE.md 里的"研究总结检查清单"（4项）必须在 compact 前全部完成。compact 会打断流程，导致下次会话需要补做。
- [入场过滤器是结构性死路]：对低胜率+高盈亏比的趋势跟踪策略，任何确认类信号系统性滞后（盈利集中在趋势启动前1-3根bar）。遇到类似策略时，直接指向出场优化和仓位管理。详见 `crypto/docs/active/validation_results.md`。
- [ATR 定仓/出场/仓位管理已全部穷尽]：ATR归一化定仓已验证最优，CE已上线，所有其余方向（Kelly/非对称/信号加权/ADX出场/KAMA等）全部无效。详见 `crypto/docs/active/validation_results.md` 和 `crypto/docs/background/trend_following_research.md`。
- [xlsx 列名匹配要用模糊查找]：TV导出xlsx的价格列名是"价格 USDT"不是"价格"，用 `col_idx.get('价格', -1)` 会取到-1，导致取到最后一列（累计P&L%）。正确做法：`next((k for k in col_idx if '价格' in k or k == 'Price'), None)`。
- [差值大小过滤等同于入场过滤器]：加"差值 > k×ATR 才入场"本质和入场过滤器一样，4标的实测 k 越大 Sharpe 越低。详见 `crypto/docs/active/validation_results.md`。
- [调研预估不等于已验证]：之前将 CE 列为"预估不值得验证"，实际回测后 IS+OOS 均正向。文献调研给出的方向判断是概率性的，"预估无效"不等于"已验证无效"，有实际数据时以回测结果为准。
- [TV 交易记录方向字段在"信号"列而非"类型"列]：TV 导出 xlsx 中，"类型"列值为"多头进场"/"空头进场"（中文），"信号"列值为"long"/"short"（英文小写）。读取方向时应优先用"信号"列的 'long'/'short'，不要只依赖"类型"列的中文关键词匹配。
- [信号强度加权仓位是软版入场过滤器]："强信号满仓、弱信号缩仓"方向本质与入场过滤器相同，已验证无效。详见 `crypto/docs/active/validation_results.md`。
- [资金费率过滤需区分"泛化双向"和"单向针对性"]：泛化双向过滤（-6.4%）无效；FR_MA7 > 0 才允许做空有效（IS+0.132/OOS+0.511）。两者不冲突：后者利用了 FR<0 时做空付费+逼空风险的非对称信息。详见 `crypto/docs/active/validation_results.md`。
- [目录结构调整后要全量扫描引用路径]：docs/ 目录结构变更（如新增 active/background/archive 子目录）后，必须检查所有 .md 文件的交叉引用，范围包括：HANDOFF.md、CLAUDE.md（各层级）、lessons.md、skills 文件、docs/ 内部文件——不只是被移动的文件本身。遗漏会导致路径失效或状态过时，本次 health_monitor.md 和 HANDOFF.md 均因此出现问题。
- [TV xlsx 格式会静默变更]：TradingView 会不定期更新导出格式（如 sheet 名 `交易清单`→`交易`，字段名变更）且不发通知。每次遇到新 xlsx 报错时，先用 `wb.sheetnames` 和打印表头确认实际格式，再修代码。分析脚本中所有 sheet 名和字段名读取都应做 fallback 兼容，不要硬编码单个名称。
- [多ETF矩阵末尾NaN导致净值假性暴跌]：不同ETF数据更新日期不同步时（如新加入的ETF比其余ETF多几天数据），`load_close_matrix` 末尾会出现大量NaN行。回测循环遍历到这些行时，持仓标的价格全为NaN，净值"假性暴跌"至仅剩现金。修复：`load_close_matrix` 截断到超过半数标的有数据的最后一天（已在 `fetch_data.py` 实现）。新增任何ETF数据源时都要检查日期对齐。
- [动量轮动策略加入新标的要先验证信号质量]：加入相关性低的资产（商品ETF）直觉上是分散化，但在Top-N动量轮动里，新标的直接参与竞争坑位。若新标的动量信号质量不如原有标的（IC低、趋势持续性差），反而稀释组合动量强度，实测净负效果。正确流程：先单独测试新标的的动量信号历史表现，再决定是否加入标的池。
- [子agent代码分析结论要手动验证]：子agent分析代码时可能误判切片逻辑。`series.iloc[i-window:i]` 不含 `i`，子agent却报告为"使用当日数据，存在前视偏差"。代码分析子agent的结论要用简短脚本验证，不要直接相信并动手改代码。


- [ETF轮动拥挤度信号"有效"结论已被推翻，见下方2026-07-08条目]：脏数据（含13处复权断层）上测得threshold=0.75, factor=0.2时夏普0.83→1.005，69%参数网格超基线，一度推翻"优化已穷尽"的结论；但换成干净数据后边际收益归零（+0.007，不显著），已从上线信号移除，当前配置是纯风险调整动量（无拥挤度）。保留此条仅作历史记录，具体原因见下方"已验证有效"条目。
- ["优化已穷尽"结论本身可被推翻]：写下"所有方向已穷尽"时，前提是"当前数据依赖下"。若数据可用性发生变化（如用价格代理绕开权限），或出现从未测试过的信号类别（如拥挤度），结论需要重新验证。不要用"穷尽"作为拒绝新方向的理由，正确判断标准是"此方向是否有逻辑支撑 + 是否经过回测"。
- [价格相关性是拥挤度的低成本代理]：拥挤度原本需要成分股持仓数据（无权限），改用ETF间滚动相关系数（60日均值→252日历史分位）效果相同甚至更好，且无数据依赖。同类问题：若目标指标无法直接获取，优先找价格层面的代理变量，不要因数据缺失直接放弃方向。
- [北向资金信号2022后已失效]：北向数据披露规则2022年后变化，信号IC从+0.015衰减至-0.178（反向），方向胜率从51.6%降至42.8%。用北向作为行业ETF轮动过滤器会降低策略表现，不可用。
- [PE高分位≠A股熊市]：用PE历史分位数定义市场状态在A股反向——PE高分位往往对应行情最强的科技/成长牛市（如2017/2020/2025年）。任何以"高估值=减仓"为逻辑的区制切换在A股都会系统性错过最大涨幅，等效于动态持仓数的失效原因。
- [表面最优配置要诊断来源]：方向A+D全样本夏普0.98看似最优，但诊断发现最长禁买段2024-08起长达693天，OOS超额来自"碰巧不操作"而非信号有效性。出现"IS期表现不错+OOS大幅超越"模式时，先检查是否有某个外生事件恰好覆盖了OOS区间。
- [A股ETF动量不同于全球多资产TAA]：Dual Momentum、skip-month、动态持仓数等在全球多资产（股/债/商品）文献中有效的改进，在A股ETF月度轮换中全部无效甚至有害。核心原因：A股行业ETF的高波动期 = 趋势最强期（如2019/2020/2024年科技行情），任何降仓机制都会错过最大涨幅。A股ETF动量来源是机构资金惯性，而非全球大类资产的宏观驱动，适用逻辑不同。
- [文献结论不等于A股结论]：国际量化文献（Antonacci/Faber/Keller/Moskowitz）的策略改进方向，移植到A股ETF月度轮换前必须回测验证，不能直接相信。A股市场结构（散户主导/政策市/T+1/无做空）与全球成熟市场差异巨大，导致很多"普遍有效"的改进在A股反向。
- [文档收尾要做全量扫描，不只改内容文件]：每次结论有实质变化，需要同步更新的地方通常有4处：① 内容文件本身（research.md / docs）② memory topic 文件（project_*.md）③ MEMORY.md 索引描述行 ④ 内容文件顶部的"当前上线结果/当前状态"摘要行。只改其中一处会留下彼此矛盾的过时快照，导致下次对话读到错误的状态。
- [ETF场内成交量不适用量价分析]：A股ETF场内成交量包含大量套利交易（折溢价套利者在折溢价时机械买卖，与行业趋势无关），月均IC=0.015，IC>0占比49.2%（随机水平）。量价确认逻辑在个股层面有效，但在ETF场内成交层面信噪比过低，不适用。遇到ETF层面的量价信号方向时，直接排除，不需要回测。
- [标的池高相关≠重复品种，去重必须用指数定义]：A股牛市行情会让所有ETF相关性虚高（如芯片ETF vs 农业ETF相关性0.997），导致相关性阈值过滤产生大量假阳性。ETF去重的正确方法是检查追踪指数是否相同，而非用价格相关性。真正的重复品种（如512100和159632同追中证1000）通过指数定义即可识别，45只ETF池中实际只有1对真正重复。
- [系统性信号会覆盖手工组合约束]：当策略已有动态信号（如拥挤度软过滤）在信号层做跨标的压制时，再叠加手工规则（如子行业组内限制2席）通常是冗余的——动态信号已经自动降低了高同质性标的的得分，手工约束不会产生增量效果。判断标准：若已有信号和新约束针对的是同一个风险来源（行业集中），优先验证已有信号是否已覆盖，再决定是否额外加约束。
- [重复问"还有什么要更新"是验收完成的信号]：用户连续追问"还有什么需要更新/总结"，且每次检查后都没发现实质遗漏，说明本轮工作已真正收尾。第三次问出来时，直接确认"已完整，无遗漏"，不要再做虚假的扫描。区别：第一次问是检查习惯（正确），第二次发现细节（正确），第三次是确认（应该终止）。
- [宏观和资金流信号在A股ETF轮动中无效]：社融IC验证弱有效(0.122)，但全量回测叠加后0/6参数超过拥挤度基线，因为社融横截面压制和A股高波动=趋势最强期的机制冲突，弱月正好可能是趋势行情启动时。ETF资金净流量反向IC验证有效(-0.062)，但全量回测0/11参数超过基线，最优0.904 vs 基线1.005，原因是资金流信号与动量得分已有很强相关（净流出往往是滞后的，趋势已经反转时才净流出）。两类信号都不能提升A股ETF月度轮动表现。
- [A股ETF月度动量信号不可削弱]：Shrinkage（截面均值收缩）、惰性调仓（持仓排名小幅下滑时不换仓）、信号EMA平滑（跨期平滑月度得分）、拥挤度衰减加权（EWM替代等权）全部有害（Δ夏普-0.15~-0.59）。根本原因：A股ETF月度动量的alpha来源是机构资金惯性，信号区分度本已接近极限，任何降低区分度（收缩/平滑）或降低响应速度（惰性调仓/平滑）的操作均净负。遇到类似"降噪/稳健性"类改进方向时，先想这个机制是否与机构惯性逻辑冲突。
- [A股月末价格索引要用实际交易日]：`resample("ME").last().index` 生成的是自然月末（如2016-04-30），不一定是交易日。用 `.loc[自然月末]` 直接索引会 KeyError。正确做法：用 `close_panel.index[close_panel.index <= m][-1]` 取 <= 自然月末的最后一个实际交易日，再用该日期索引面板。
- [文献因子IC与实测差距要预先说明]：文献报告的因子ICIR（如反转因子 -0.244）通常来自全A股含小盘股，限定沪深300/中证500后信号会系统性更弱（实测约 -0.10）。遇到文献因子时，先说明"这是全A股结果，沪深300/中证500可能打折"，不要直接用文献数字作为实测预期。
- [低波动因子在A股选股中是非对称因子]：截面IC验证（ICIR 0.40）看似显著，但选股回测跑输基准3%/年。根本原因：低波动溢价在A股牛市（2019-2021）反向，高波动成长股才是最大涨幅来源。IC验证的全样本均值被熊市/震荡市年份拉高，掩盖了牛市反向的风险。做A股选股因子验证时，除看全样本ICIR外，必须分年度检查IC方向的稳定性，尤其是牛市年份。
- [行业内因子排名能提升信号质量]：对EP做行业内截面排名（而非全截面），ICIR从+0.255提升至+0.321，且在2019-2022成长牛市期间维持正向（全截面EP在行情强的成长行业系统性失效）。遇到价值类因子在成长牛市反向时，优先尝试行业中性化，而非放弃该因子。
- [盈利增速稳定性是A股选股的鲁棒因子]：净利润YoY增速的历史标准差（8季度）取负，ICIR +0.322，2016-2026全部年度均维持正IC（含2019-2022成长牛市）。机制：盈利稳定不依赖"便宜"或"低波动"，是公司质量的直接度量，对A股市场状态切换不敏感。遇到价值/低波动因子牛市失效时，盈利稳定性是第一候选替代方向。
- [IC好+选股差的诊断标准路径]：因子截面IC显著但选股回测跑输基准时，标准诊断顺序：① 看年度IC分拆（发现某几年系统性反向）→ ② 找反向年份的市场状态（牛市/熊市/成长行情）→ ③ 分析因子经济学逻辑是否与该状态冲突 → ④ 决定是换因子还是加市场状态条件。不要在没诊断前直接加更多因子。
- [因子数量少时LGB不优于线性加权]：因子数量<10且截面样本有限（500只×125月）时，LightGBM无法学到有效非线性交互，结果与线性加权持平或更差。LGB适合因子数量扩充到15+个后再验证，不是少因子阶段的优化手段。
- [自适应权重IS好/OOS差=过拟合信号]：滚动IC加权、硬切换等自适应权重机制，若IS改善幅度越大则OOS越差，是过拟合的典型特征。根本原因：A股风格切换剧烈且不可预测，基于历史IC的自适应权重必然滞后1期以上。遇到IS/OOS差距随IS改善而扩大的模式，直接判定过拟合。
- [分析师预期修正因子需先查覆盖率]：tushare report_rc 中证500覆盖率仅28.6%（一个月约143只），不足以做截面选股。使用任何外部数据源构造因子前，先验证在目标指数内的覆盖率，低于60%时直接放弃，不要花时间下载和构造信号。
- [换指数不能解决因子在牛市反向的问题]：沪深300 V2全样本超额-2.1%，比中证500（-1.5%）更差，同样2019起系统性反向。大盘股成长行情更集中，反而放大了因子失效。遇到"换指数改善因子有效性"方向时，先问：失效的根本原因是行业暴露还是市值暴露？若是A股风格切换（成长/价值），换指数不会有效。
- [行业名称体系要核对来源，不能假设一致]：`etf_stock_hybrid_backtest.py` 用申万行业名（"电子"/"计算机"/"电力设备"）做 ETF→行业映射，但误用了 `tushare stock_basic.industry`（证监会旧分类，110个细分行业，"半导体"/"全国地产"）做实际匹配，两套词表仅"银行"偶然重合，导致29个行业ETF槽位中28个查无候选股票直接降级为ETF直持，回测跑出"超额恰好为0.0%"这种过于工整的数字——这是识别此类bug的信号。正确数据源是 `pro.index_classify(src='SW2021')` + `pro.index_member_all()`（已缓存至 `a_stock/data/stock_sw_industry.parquet`）。任何"按行业名做跨表匹配/连接"的代码，写之前先打印两侧数据源的行业名集合核对是否为同一命名体系，不要假设字符串相同。**区分风险场景**：跨表按名字匹配（如ETF行业名↔股票行业名）对分类体系敏感，必须核对；组内相对排序（如"行业内EP排名"只需分组关系，不比较组名字符串）对分类体系粒度不敏感，用110类细分或31类粗分都不影响IC有效性，只是文档标注要写实际用的分类体系，不能想当然写"申万"。
